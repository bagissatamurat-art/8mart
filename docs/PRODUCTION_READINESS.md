# 8mart — что готово и что осталось до запуска

Состояние на 14.10.2026. Приложение — ветка `backend-connect`; бэкенд — `core`, ветка `8mart/storefront-api`, развёрнута на проде (`https://dukenfy-api.8mart.kz/api/v1/store`); новый сайт — `8mart-site`, ветка `backend-connect`, развёрнут на `https://new.8mart.kz`. Контракт слоя — `STOREFRONT_API.md` в репозитории бэкенда, устройство приложения — `AGENTS.md`, состояние сайта — `BACKEND_STATUS.md` в его репозитории.

Кто: **Вы** — решения, ключи, аккаунты · **B** — бэкенд · **A** — приложение · **Ф** — фронт-разработчик.

## Что работает на настоящем бэкенде

С `API_URL` в `env.json` приложение берёт с сервера всё:

| Что | Как |
|---|---|
| Вход и регистрация | через Telegram-бота: «Старт» → «Поделиться номером»; номер подтверждает Telegram, кода нет. **Ждёт токен бота** — см. ниже |
| Профиль | имя, выход, удаление аккаунта |
| Каталог, поиск, карточка товара, букеты S/M/L | снимок каталога core, цены и фото — продовые |
| Города, точки самовывоза | филиалы core |
| Адрес доставки: подсказки, карта, зона | DaData и Mapbox через сервер; свой ключ DaData приложению больше не нужен |
| Корзина | наличие и цена своего филиала проверяются на сервере; перед оплатой — ещё раз |
| Стоимость доставки | по зоне доставки, считает сервер |
| Окна доставки | с сервера, по времени Казахстана |
| Заказ | сервер сам определяет филиал, цены и итог; суммы из приложения не принимаются |
| Оплата Kaspi | ссылка на оплату, а без терминала у филиала — счёт от оператора на номер покупателя |
| Оплата картой | страница шлюза BCC |
| Статус заказа | настоящие этапы, время, слот, курьер; обновляется раз в 15 с и при возврате в приложение |
| Отмена заказа | на сервере; уже в доставке — отказ с объяснением |
| «Мои заказы» | заказы покупателя с сервера; заказ вошедшего покупателя виден только ему |
| Контакты поддержки, способы оплаты, порог бесплатной доставки | `GET /app/config` |
| Сторис | с сервера |

Скрыто, пока нет серверной логики: промокоды, бонусы, сохранённые карты. Приложение не показывает выдуманных чисел.

Проверено: 68 тестов приложения и 328 тестов бэкенда; сквозные прогоны на копии продовой базы — «каталог → корзина → заказ → статус → отмена» и «вход через бота → профиль → заказ → выход → удаление аккаунта» (сообщения бота на стенде подставлялись вручную); запуск в симуляторе iPhone на продовых данных.

## Что остаётся до запуска

### 1. Вход — нужен токен бота

Вход через Telegram-бота написан и развёрнут на проде, но выключен, пока серверу не дали бота: приложение показывает «Вход через Telegram сейчас недоступен».

- **Вы:** создать бота у @BotFather (`/newbot`) и передать токен. На сервере это одна переменная — `STOREFRONT_TELEGRAM_BOT_TOKEN`; имя бота и адрес для его сообщений сервер настраивает сам при запуске.
- После этого — один настоящий вход с телефона: в Telegram стенд не ходил, поэтому сама доставка сообщений бота вживую ещё не проверена.
- Как устроен вход: приложение получает ссылку на бота, покупатель нажимает «Старт» и «Поделиться номером», приложение само получает сессию. Чужой контакт и чужая ссылка не принимаются; ссылка живёт 10 минут и срабатывает один раз.
- Ограничение способа: тот, кто убедит человека открыть чужую ссылку входа и поделиться номером, войдёт в его аккаунт. Бот предупреждает об этом в сообщении («если вы не входили — ничего не нажимайте»). В аккаунте сейчас нет ни карт, ни бонусов — только заказы и имя.
- Вход по коду в WhatsApp (есть в ветке `main` бэкенда, через Radist.Online) не подключён: по решению 13.10 вход пока только через Telegram.
- Адреса и избранное пока хранятся на устройстве, на сервер не переехали. **B + A**

### 3. Бэкенд

- **Тестовая сумма Kaspi.** `kaspi.test-build.force-amount-enabled` по умолчанию включена, и на проде не переопределена: через терминал Kaspi счёт выставится на 0,10 тг. До подключения терминалов её нужно выключить (`KASPI_TEST_BUILD_FORCE_AMOUNT_ENABLED=false`). Не трогал — входит в «план безопасности», см. ниже.
- **Оплата картой не проверена:** шлюз BCC на проде включён, но настоящий заказ с оплатой картой не создавался. Нужен один пробный платёж.
- **Возврат из оплаты** ведёт на страницы действующего сайта (`/payment/result`). Когда выйдет новый сайт — поменять `STOREFRONT_PAYMENT_RETURN_URL` на `/pay/return?order={id}`.
- **Ветка `8mart/storefront-api` не отправлена в GitLab:** `gitlab.fri-to.kz` отвечал 502. Код есть локально и на сервере.
- **Push:** `POST /devices` и отправка уведомлений при смене статуса — после проекта Firebase.

### 4. Приложение

- **Push** — после Firebase (`lib/core/push.dart`); с бэкендом приложение пока не спрашивает разрешение.
- **Обязательное обновление** — нужен `package_info_plus` и `minVersion` на сервере.
- **Возврат из оплаты в приложение** — нужны Universal Links / App Links (`applinks:8mart.kz`, файлы на домене). Сейчас покупатель возвращается в приложение сам, статус обновляется сразу.
- **Android не собирался:** на этой машине нет Android SDK. Правки под Android (вход по отпечатку: `FlutterFragmentActivity`, разрешение `USE_BIOMETRIC`) сделаны, но не проверены сборкой.
- **Ключ DaData в `env.json`** при сборке попадает в приложение, хотя с бэкендом не используется. Для релизной сборки убрать `DADATA_API_KEY` из `env.json`.
- **Условия получения в карточке товара** («Храним 24 часа») — тексты из макета; нужны настоящие от бизнеса.
- **Казахский перевод** — черновик, нужна вычитка носителем.
- **CI** (`.github/workflows/flutter.yml`): ошибки анализа и тестов игнорируются (`|| true`), а ключ DaData попадает в публичную веб-сборку. С бэкендом ключ в приложении не нужен — убрать из CI. **Ф**
- **Экран «Вопросы и ответы»:** в отладке `ListTile` внутри `DecoratedBox` даёт предупреждение (отклик нажатия не виден). На работу не влияет. **Ф**

### 5. Сайт (`8mart-site`)

Подключён к бэкенду и развёрнут на сервере как предпросмотр: `https://new.8mart.kz` (контейнер `mart8-site`, поисковикам закрыт). На `8mart.kz` по-прежнему работает прежний сайт.

- **Переключение `8mart.kz` на новый сайт** — после токена бота и одного настоящего входа: на новом сайте заказ оформляет только вошедший покупатель, а на прежнем сайте заказы идут (последний — 12.10). Переключение — правка одного блока nginx; прежний сайт остаётся в контейнере `client` для отката. **Вы** (решение) **+ B**
- **Товары в каталоге.** На витрине, кроме 9 букетов, видны 74 позиции «Продукты» и «Товары» (сладости, батарейки, уголь), заведённые в базу одним днём 07.09. Если это не настоящий ассортимент — скрыть их в CRM до переключения. **Вы**
- Чего на сайте нет, потому что нет в бэкенде: промокоды, бонусы, сохранённые карты, вход по коду; адреса и избранное хранятся на устройстве.
- Проверено: 112 тестов сайта; в браузере на стенде с копией базы — «вход через бота → оформление → заказ → отмена → кабинет → выход» на экране компьютера и телефона; на `new.8mart.kz` — каталог, товар, корзина, проверка корзины на сервере. Оплата картой и ссылка Kaspi проверены только с подставленными ответами сервера.

## Безопасность core — план (по решению 30.09 не правилось)

Новый слой `/api/v1/store` этих проблем не имеет, но старые пути остаются открытыми, пока работает действующий сайт.

1. **Скидка и доставка от клиента.** Старый `POST /public/orders` вычитает `discountAmount` и берёт `deliveryAmount` из запроса. Исправление: игнорировать оба, считать на сервере.
2. **Подтверждение оплаты Kaspi открыто всем.** `PATCH /orders/*/payment/kaspi/confirm` — любой, кто знает id заказа, помечает его оплаченным. Исправление: только сотрудник с доступом к филиалу.
3. **Тестовая сумма Kaspi 0,10 тг** включена по умолчанию. Исправление: по умолчанию выключена.
4. **Секреты значениями по умолчанию** в `application.properties`: `jwt.secret`, токен бота мониторинга, пароль сертификата BCC, логин iiko. Исправление: только переменные окружения; засвеченные ключи перевыпустить.
5. **Заказ по uuid.** Старый `GET /public/orders/{id}` отдаёт телефон и адрес любому, кто знает id. В новом слое заказ вошедшего покупателя виден только ему; заказ гостя по-прежнему открывается по id. Исправление для старого пути: отдавать телефон маской и без адреса.
